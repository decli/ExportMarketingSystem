## 一、市场与渠道格局的三个结构性变化

### 变化 1：平台红利结束，获客从「等询盘」转向「主动开发 + 内容复利」

2026 年的实际数据：阿里国际站活跃买家仍超 2000 万，但同质化竞争导致平均点击转化率仅 **1–3%**，P4P 点击成本一年上涨约 **35%**。一个典型样本——深圳某小型电子配件厂，2024 年入驻，基础出口通年费 3 万 +，叠加 P4P 月均 5000 元，全年投入约 **9 万元，收到 420 封询盘，成交 7 个客户，客单价不足 $2000**。相当于每个成交客户获客成本 1.3 万元，而毛利可能不足以覆盖。

展会同样承压：一次海外工业展的展位费 + 样品运输 + 差旅动辄数十万，优质询盘屈指可数。

与之相对，**独立站 SEO 的复利效应开始兑现，海外社媒是增速最快的增量入口，海关数据让主动开发变得可量化**。

> **对产品的含义**：系统的重心不能是「把已有询盘管起来」的传统 CRM。必须把**线索获取（Lead Acquisition）**做成一等公民，且与 CRM 同栈——否则就是又一个「等米下锅」的客户管理软件。

### 变化 2：AI 搜索改写了流量分配规则，SEO 必须升级为 SEO + GEO 双引擎

美国 Google 搜索中约 **58% 的查询已是「零点击」**——用户直接从 AI 生成的答案中获取信息，不再点进任何网站。

这不意味着独立站没用了，而是意味着**独立站的角色从「接流量的落地页」变成了「喂给 AI 的可信语料源」**。2026 年主流打法是 SEO + GEO（Generative Engine Optimization）双引擎：SEO 是地基，保证收录与稳定排名；GEO 是上层建筑，把品牌信息以 **AI 语义友好的结构化方式**组织，并建设权威信源，去争夺 AI 回答里的**被引用位**。

同时一个现实约束：截至 2026 年 7 月，**尚没有纯 AI 建站系统能完全独立建成功能、生态、前后端全可控的商业站**。AI 建站的正确定位是「大规模生产 + 人工把关」，不是「一键全自动」。

> **对产品的含义**：内容与站群不是附属模块，而是获客主引擎之一。需要「产品/素材库 → AI 内容工厂 → 多语言站群 → 表单/WhatsApp 入口 → 线索回流 CRM」的完整闭环，并且内容要输出 **Schema.org 结构化数据、FAQ、可被引用的事实段落**（GEO 资产），而不只是堆关键词。

### 变化 3：触达侧的门槛从「能不能群发」变成「能不能送达 + 合不合法」

**送达率**：仅配置 SPF，邮件大概率进垃圾箱甚至被拒收；DKIM 是 Gmail 极为看重的信任指标；DMARC 决定认证失败时的处置策略并提供报告。专业服务商靠专属 IP 池、智能发送速率控制、与主流 ISP 建立信誉来把投递率从 60% 拉到 90%+。

**合规**：
- **GDPR**：B2B 冷邮件在 EU 并非绝对需要 explicit consent，可依据 Art. 6(1)(f) 正当利益（legitimate interest），但**必须完成 LIA（正当利益评估：目的测试 / 必要性测试 / 平衡测试）并留档**。2026 年监管趋势在向 opt-in model 收紧。罚则区间从小企业 €500 到 €900,000+。
- **邮件页脚硬性要求**：公司名、实际地址、**可用的退订链接**、说明联系原因——一次性覆盖 CAN-SPAM / GDPR / CASL 的大部分要求。
- **CAN-SPAM**：退订机制在发信后至少保持 30 天有效，收到退订须在 **10 个工作日内**移除。
- **WhatsApp Business API**：opt-in 是**强制**的，Meta 要求提供**书面同意证据**才批模板；「CRM 里存了号码」不构成群发许可。在 EU 做营销消息需要**两重许可**：WhatsApp 专项 opt-in + GDPR 合法性基础，且**捆绑勾选、默认勾选无效**。

> **对产品的含义**：合规不能做成「设置页里的一个开关」。必须是贯穿数据采集、模板审批、发送执行、退订处理、审计留痕的**横切能力**，并且默认安全（secure by default）。这恰恰是国内多数外贸营销工具最薄弱、也最容易变成客户重大风险的一环——**做扎实就是差异化护城河**。

## 二、角色画像：他们每天到底在干什么

### 2.1 业务员（Sales / 外贸跟单）一天的真实节奏

时差是外贸最被低估的约束。参考系统截图顶栏常驻「JP 日本 20:03」这样的**客户时区显示**，不是装饰，是刚需。

| 时段 | 干什么 | 真实痛点 |
|---|---|---|
| 08:30–10:00 | 打开邮箱看**昨夜欧美来信**（客户在他们的白天发的），排优先级 | 邮件、WhatsApp、平台站内信、网站表单**分散在 4 个地方**；不知道哪封重要，凭感觉排序 |
| 10:00–12:00 | 回询盘、报价、寄样安排 | 报价要翻历史价格、算汇率、查运费、问工厂成本；每次都重做一遍 |
| 13:30–15:00 | 跟单：催生产进度、确认验货、订舱、单证 | 客户的要求「一点不漏地传达给生产和品质部门」——靠微信和记忆，最容易出错 |
| 15:00–18:00 | **开发新客户**：海关数据筛买家、LinkedIn 找决策人、Google 搜同行客户、发开发信 | 最该做但最先被挤掉的事；发出去石沉大海，不知道有没有送达、有没有打开 |
| 20:00–22:00 | 跟美洲客户视频/WhatsApp | 私人手机号沟通，记录留在个人设备上 |

**高频失败模式（调研中反复出现）**：
1. **询盘回不出去**——邮件格式不得体或内容过多被拦截；模板化回复过于平淡，客户失去回复兴趣。
2. **PI 被误当成订单**——「PI 从来都不代表要下单，PI 只是客户让你通过书面确认报价条件而已，PI 跟订单还差着很远」。系统若把「发出 PI」直接算成商机赢单，预测必然虚高。
3. **客户「蒸发」**——跟进节奏靠人脑记忆，3 次没回就放弃，没有系统化的复跟与盘活机制。
4. **信息在交接处丢失**——销售→生产→品质→单证，每一次转手都是一次信息衰减。

### 2.2 老板 / 外贸经理关心什么

调研中中小外贸企业客户管理的**四大痛点**极其一致：
1. **客户资产私有化**——「人走客凉」，员工离职后客户信息一片空白，客户回来问上一个联系人时得从头开始。
2. **客户分层混乱**——「一锅乱炖」，大客户和散户在同一个列表里。
3. **跟进无标准无记录**——不知道业务员今天做了什么、说了什么、承诺了什么。
4. **无客户盘活机制**——沉睡客户躺在库里没人碰。

老板真正想看的（而不是「今天发了多少封邮件」）：
- **钱花在哪个渠道、回报如何**（阿里 vs 独立站 vs 展会 vs 主动开发的单位获客成本与成交额归因）
- **客户资产是否在公司手里**（联系方式、沟通记录、报价历史的沉淀率）
- **毛利与风险**（汇率敞口、应收账款账龄、单一客户依赖度）
- **团队产能与健康度**（人均产出、漏斗转化率、跟进及时性、僵尸客户占比）

同时要警惕：KPI「层层加码」会导致销售消极，中小企业慎用纯 KPI 考核。系统应更多提供**过程可视 + 异常提醒**，而非考核鞭子。

> **对产品的含义**：老板视角和业务员视角是**两套完全不同的信息架构**，不能靠一个「管理员看到更多菜单」糊弄过去。产品必须内置角色化工作台。

## 三、外贸业务流程建模（系统的领域骨架）

### 3.1 主流程（获客到复购的完整链路）

```
线索获取                 培育与转化                    交付与回款              复购
─────────            ────────────────           ──────────────        ────────
海关数据 ┐                                        PI 确认 ┐
LinkedIn ├→ Lead ─┬→ Contact ─→ Inquiry ─→ Opportunity ─→ Quotation ─┤        ┌→ Reorder
Google   │  线索  │  联系人      询盘        商机          报价       ├→ SO/合同 │
地图/展会 │        └→ Company                                         │   订单   │
独立站表单┤           客户公司                                         ↓         │
站群/内容 │                                                     生产跟单 → 验货  │
访客识别 ┘                                                          ↓            │
                                                              出运/单证 → 收款 ──┘
```

### 3.2 核心领域对象与关键约束

| 对象 | 关键字段 | 容易被做错的地方 |
|---|---|---|
| **Lead 线索** | 来源渠道、原始数据快照、AI 评分、去重指纹 | 必须保留**原始来源快照**（哪条提单/哪个 LinkedIn profile），否则无法做归因也无法应对 GDPR 数据来源质询 |
| **Company 客户公司** | 国家、时区、分层(KA/A/B/C)、归属人、公海/私海状态 | **时区**必须是一等字段；公海回收规则是解决「客户资产私有化」的关键机制 |
| **Contact 联系人** | 邮箱、WhatsApp、LinkedIn、职级、**各渠道 opt-in 状态与证据** | opt-in 状态要**按渠道分别存储并留证据**，不能一个布尔值走天下 |
| **Inquiry 询盘** | 渠道、原文、AI 摘要、意向标签、SLA 时钟 | 询盘 ≠ 商机。一个客户可以多次询盘；SLA 首响时钟从**收到**开始，不是从「业务员看到」开始 |
| **Opportunity 商机** | 阶段、金额、币种、预计成交日、赢率 | 阶段推进必须有**客观事件驱动**（收到目标价 / 寄样确认 / PI 已签回），不能靠销售自己拖卡片 |
| **Quotation 报价** | 版本、价格条款(FOB/CIF)、有效期、汇率锁定 | 报价必须**版本化**，且记录成本快照，否则事后无法核算毛利 |
| **PI 形式发票** | 规格/颜色/材料/价格/数量/包装/运输贸易方式/付款方式/交期 | **PI 已发 ≠ 赢单**，应设为独立阶段并单独统计「PI 转化率」 |
| **Order 订单** | 生产节点、验货、订舱、单证清单、收款计划 | 交期节点要能反向触发对客户的**主动进度通报**（最有效的复购铺垫） |
| **Message 消息** | 渠道、方向、送达/打开/回复状态、关联对象 | 邮件与 WhatsApp 必须归一到同一条客户时间线，否则「客户 360」是假的 |

### 3.3 状态机（商机阶段，带客观进入条件）

```
新建线索 → 已触达 → 有回应 → 需求明确 → 已报价 → PI已发 → 已签约/收定金 → 生产中 → 已发货 → 已回款 → 复购
   ↓         ↓        ↓         ↓          ↓        ↓
             └──────── 无响应回收至公海 ───┘     丢单（记录丢单原因：价格/交期/认证/竞品/无预算）
```

丢单原因是**必填结构化字段**——这是老板能拿到的最有价值的一份数据，也是 AI 后续优化话术的训练信号。

## 四、竞品格局与我们的空位

| 类型 | 代表 | 强项 | 结构性短板 |
|---|---|---|---|
| 平台系 CRM | 小满 OKKI | CRM 功能行业首屈一指，AI 识别客户意向、生成跟进建议 | **获客端严重依赖阿里国际站询盘数据，主动开发能力较弱**；平台依赖即命门 |
| 传统外贸 ERP | 孚盟、富通天下 | 单证、财务、流程完整，老牌可靠 | 偏内部管理，营销/获客与 AI 能力弱，交互老旧 |
| 营销云系 | 询盘云 | 多渠道触达、营销自动化 | 交付重、偏大客户，中小团队上手成本高 |
| 拓客工具 | 腾道、贸小七、跨境魔方等 | 海关数据 + 搜索开发 | 只解决「找到人」，找到之后的转化/交付/沉淀断链 |
| 海外 AI SDR | Reply.io（含 Jason AI）、11x、B2B Rocket | 多渠道序列编排（Email/LinkedIn/SMS/WhatsApp）、十亿级联系人库、AI SDR 成熟 | **完全不懂中国外贸场景**：没有海关数据、没有 PI/报关/跟单、没有汇率与佣金、中文支持差、国内访问与付费不便 |

**空位很清楚**：

> 没有一个产品同时做到 ——
> ① 主动获客（海关数据 + 社媒 + 内容站群）
> ② 全渠道合规触达（送达率与 GDPR/WhatsApp 合规内建）
> ③ 懂外贸的转化与交付（询盘→报价→PI→订单→单证→回款）
> ④ 老板要的资产沉淀与渠道 ROI 归因
> ⑤ 且以 **AI Agent 编排**而非「AI 小助手插件」的方式重构工作流。

这就是本系统的定位。价格锚点参考：SaaS 版外贸 CRM 约 3000 元/年（10 人），拓客类工具月付 159 / 年付 1199（含 2 子账号），通用 CRM 每用户每月 $20–300。我们的定价策略见 `03-路线图与商业化.md`。

## 五、从调研到设计的结论清单

| # | 调研结论 | 产品设计动作 |
|---|---|---|
| 1 | 平台转化率 1–3%，获客成本高企 | 线索雷达（多源获客）与 CRM 同栈，不做「纯 CRM」 |
| 2 | 58% 零点击，GEO 兴起 | 内容工厂输出结构化 GEO 资产，站群作为获客引擎 |
| 3 | 纯 AI 建站尚不能全自动 | 建站采用「AI 生产 + 人工把关 + Git 部署」模式 |
| 4 | 送达率取决于 SPF/DKIM/DMARC + 预热 | 内建「发信域健康度」体检与自动预热调速 |
| 5 | GDPR 需 LIA 留档、WhatsApp 需 opt-in 证据 | 合规中心：LIA 向导、opt-in 证据链、退订中心、审计日志 |
| 6 | 时差是刚需约束 | 客户本地时间、最佳发送时窗、夜间询盘晨间聚合简报 |
| 7 | 询盘分散在 4 个渠道 | 统一收件箱（Email + WhatsApp + 表单 + 平台） |
| 8 | PI ≠ 订单 | PI 独立阶段 + PI 转化率指标，避免预测虚高 |
| 9 | 人走客凉、客户资产私有化 | 公海/私海机制 + 回收规则 + 客户资产沉淀率指标 |
| 10 | 中小企业慎用强 KPI | 老板看板以「过程可视 + 异常预警」为主，而非考核排名唯一 |
| 11 | 交接处信息衰减 | 订单节点驱动的跨部门任务与客户主动通报 |
| 12 | 海外 AI SDR 不懂外贸 | Agent 工具集内置外贸专用能力（海关数据检索、报价测算、PI 生成） |
