# 01 · 产品方案：EMS 外贸营销系统

> 依据 `00-行业调研与业务流程.md` 的结论展开。本文回答：**做什么、给谁做、凭什么赢、长什么样**。

---

## 一、产品定位

**一句话**：EMS 是面向中小外贸企业的 **AI Agent 驱动的全链路增长系统**——从「找到买家」到「收到货款」跑在同一套数据上。

**与三类现有产品的边界**：

- 不是「等询盘上门的 CRM」→ 我们把**主动获客**放在系统入口第一屏。
- 不是「只找客户的拓客工具」→ 我们把线索一路承接到**订单与回款**，让 ROI 可闭环归因。
- 不是「加了个 AI 按钮的老系统」→ AI 是**编排层（Agent Runtime）**，能自己跑目标、拆任务、调工具、留痕、被接管，而不是散落在各页面的「智能生成」按钮。

**产品信条（写给团队的四条设计原则）**：

1. **数据必须闭环**。任何一次触达、任何一条线索，都要能追到它带来的成交额；追不到的功能不做。
2. **默认合规**。所有对外发送路径，默认经过 opt-in 校验、退订页脚注入、审计留痕。合规不是可选项。
3. **AI 可接管**。Agent 的每一步都可暂停、可查看依据、可人工改写后继续。不做黑盒自动发送。
4. **老板与业务员是两个产品**。同一份数据，两套信息架构。

## 二、目标用户与场景分层

| 分层 | 画像 | 核心痛点 | 首日价值（Day-1 Value） |
|---|---|---|---|
| **L1 SOHO / 1–3 人** | 个人外贸、初创工厂业务组 | 没钱投平台，全靠自己发开发信；工具散、记不住 | 接入邮箱 10 分钟内，自动整理出「过去 12 个月联系过但没成交的 47 个客户 + 建议复跟话术」 |
| **L2 中小工厂 / 5–30 人** | 有 1–2 个平台店铺 + 少量老客户 | 客户资产在业务员手里；获客单一；跟单靠微信 | 一屏看清「谁在跟谁、卡在哪一步、哪些客户 30 天没动静」 |
| **L3 成长型外贸公司 / 30–200 人** | 多品类、多市场、有独立站与投放预算 | 渠道 ROI 说不清；跨部门交接掉链子；合规风险 | 渠道归因看板 + 交付协同 + 合规审计 |

**首发聚焦 L2**——L1 付费能力弱但可做 PLG 免费层引流，L3 交付重需要销售团队。L2 是钱、痛、量三者的交集。

## 四、模块详细设计

### ① 线索雷达（获客）

**要解决的**：业务员下午本该开发客户，但总被杂事挤掉；即使做了也不知道找的人对不对。

**数据源矩阵**（每个源是一个可插拔 Connector）：

| 源 | 拿到什么 | 适用场景 | 成本 |
|---|---|---|---|
| 海关数据 | 80+ 国官方进出口记录：买卖双方、品名、数量、金额、频次、现有供应商 | 找**正在真实采购**的买家，看竞品客户 | 采购制，按查询/条数 |
| LinkedIn | 决策人姓名、职级、公司规模 | 找到**能拍板的人**，绕过 info@ | 账号风控敏感 |
| Google / Bing 搜索 | 行业关键词下的分销商、批发商官网 | 长尾市场、细分品类 | 低 |
| Google Maps | 本地经销商、实体门店 | 建材/设备/汽配等落地型品类 | 低 |
| 展会名录 | 参展商名单 | 高意向、可线下跟进 | 中 |
| 官网访客识别 | 匿名访客 → 公司识别 | **最高意向**：主动来看过你的产品 | 中 |
| 表单/在线咨询 | 直接留资 | 最高转化 | — |

**关键设计（不是简单列表）**：

1. **AI 线索评分（0–100）**，四个维度可解释，而非黑盒分数：
   - **需求匹配度**：海关记录中的 HS Code / 品名与我方产品库匹配度
   - **采购活跃度**：近 6 个月提单频次与趋势（数据新鲜度极重要——三个月前的数据可能意味着客户已经跟别人合作了，故对数据源做**更新频率标注**：日更/周更/月更）
   - **切入可能性**：现有供应商集中度（单一供应商=难切入但值钱；多供应商=好切入）
   - **可触达性**：是否已拿到决策人邮箱/LinkedIn/WhatsApp
2. **去重与主数据合并**：同一家公司从 3 个源进来必须合并成一条，保留三份来源快照（用于归因 + GDPR 数据来源举证）。
3. **一键成案**：线索 → 自动补全公司信息 → 建议归属人（按语言/市场/负载均衡）→ 推荐触达序列。

**业务员视角的呈现**：不是给一张 5000 条的表，而是**每天早上 20 条「今日建议开发」**，每条附一句「为什么是他」。这是产品的信任建立点。

### ② 内容工厂 + AI 建站（SEO/GEO 引擎）

**要解决的**：独立站是长期复利资产，但中小外贸做不动内容——不会写英文、不懂 SEO、更没听过 GEO。

**工作流**：

```
产品/素材库 ──→ 选题雷达 ──→ 大纲 ──→ 多语言成文 ──→ 人工把关 ──→ 站群发布 ──→ 效果回流
  (SKU/图片/     (关键词+     (AI)    (AI, 12+ 语种)  (必经!)      (Git部署+CDN)  (排名/收录/
   认证/参数)     竞品缺口+                                                        线索/AI引用)
                  AI搜索问题)
```

**GEO 资产（区别于传统 SEO 的关键）**——每篇内容自动产出：
- Schema.org 结构化数据（Product / FAQPage / Organization / HowTo）
- **可被 AI 直接引用的事实段落**：明确的参数表、对比表、标准与认证声明
- FAQ 块（直接对应 AI 搜索里用户会问的问题）
- 权威信源建设建议（行业目录、标准机构、B2B 媒体）

**站群管理**（对应参考截图 2 的形态，但更进一步）：
- 一个母站 + N 个语言/品类子站，**母子站关系显式建模**（避免重复内容惩罚：hreflang、canonical 自动生成）
- 构建状态、上线状态、版本号、一键回滚
- **SEO/GEO 体检**：收录数、核心词排名、页面速度、结构化数据校验、AI 引用监测
- Git 部署 + CDN，站点产物是静态资源（安全、快、便宜）

**边界说明（诚实的产品定位）**：AI 负责**大规模生产与优化**，人负责**事实校验与品牌把关**。系统在发布前强制一次人工确认——这既符合当前技术现实，也是对客户品牌的保护。

### ③ 触达中心（序列编排 + 送达率 + 合规）

**多渠道序列（Sequence）**，可视化编排：

```
Day 0  邮件：价值切入（引用他的采购记录，不群发感）
   ↓ 未打开 3 天 → 换标题重发（不同时段）
   ↓ 已打开未回复 5 天
Day 5  LinkedIn：连接请求 + 一句话
   ↓
Day 8  邮件：案例 + 具体报价区间
   ↓ 有回复 → 【退出序列，转人工】★
Day 12 WhatsApp（仅当 opt-in 已获得）：简短跟进
   ↓
Day 20 邮件：最后一次 + 明确退出选项
   ↓ 无响应 → 转入「培育池」，季度复跟
```

**「有回复即退出序列并转人工」是硬规则**——调研中「模板化回复导致客户失去回复兴趣」是首要失败模式，自动化必须在人味开始的地方停下。

**送达率保障（内建，不是外挂）**：
- **发信域健康度仪表盘**：SPF / DKIM / DMARC 配置校验、DMARC 报告解析、退信率、垃圾投诉率、域名年龄
- **自动预热**：新域名/新邮箱按曲线爬坡发送量，系统强制限速，不给用户「一键群发 5000 封」的自毁按钮
- **多域名池 + 身份隔离**：冷开发用独立子域，不污染主域（保护公司主邮箱信誉）
- **发送时窗优化**：按客户**本地时间**投递（周二~周四上午最优），而非按业务员的时间

**合规内建**：
- 页脚自动注入：公司名 + 实际地址 + 可用退订链接 + 联系原因说明
- **LIA 向导**：为每个开发场景生成并存档正当利益评估（目的/必要性/平衡三段论）
- **退订中心**：全局退订名单，跨序列跨账号生效，退订 24 小时内（远严于 CAN-SPAM 要求的 10 个工作日）从所有序列移除
- **WhatsApp opt-in 证据链**：来源、时间、IP、原始表单快照，模板需通过审批才能发送；未 opt-in 的联系人在 UI 上**物理禁用** WhatsApp 发送按钮

### ④ 统一收件箱 + 商机 + 报价/PI（转化）

**统一收件箱**：邮件（IMAP/OAuth）、WhatsApp、网站表单、平台站内信汇聚一处。每条会话自带：
- **AI 摘要**（3 行内说清客户要什么）
- **意向标签**（询价 / 要样品 / 谈交期 / 议价 / 投诉 / 无关）
- **SLA 首响时钟**（从「收到」开始计时，红黄绿）
- **建议回复草稿**（引用产品库真实参数与历史成交价区间，可一键改写语气：正式/热情/简洁）
- **夜间来信晨间简报**：8:30 自动生成「昨夜 9 封新询盘，3 封高意向，建议先回 XX」

**商机看板**：阶段推进需**客观事件**支撑（见 00 文档状态机）。业务员拖卡片时若无对应事件，系统提示「缺少依据」——这是让预测数据可信的关键约束。

**报价与 PI**：
- 报价单版本化，每版**冻结成本快照 + 汇率**，事后可算真实毛利
- 价格条款（EXW/FOB/CIF/DDP）自动换算，含运费与保险估算
- **PI 生成**：规格、颜色、材料、价格、数量、包装方式、运输贸易方式、付款方式、发货时间——一次填齐，多语言输出，带电子签
- **PI ≠ 赢单**：系统单独统计「PI 转化率」，老板看板明确区分「已发 PI 金额」与「已签约金额」

---

### ⑤ 订单与交付

- **订单节点甘特**：定金到账 → 备料 → 生产 → 验货 → 订舱 → 报关 → 开船 → 到港 → 尾款 → 清关
- **节点驱动的客户主动通报**：每个关键节点自动生成给客户的进度邮件草稿（「您的订单已完成验货，附图 12 张」）——调研显示这是最有效、最被忽视的复购铺垫
- **单证清单**：合同、发票、装箱单、提单、原产地证、报关单；缺件红灯
- **跨部门任务**：销售确认的客户特殊要求，自动生成生产/品质部门的待办卡片并要求签收（堵住「信息在交接处衰减」的漏洞）
- **收款与账龄**：分期收款计划、逾期预警、汇率损益

### ⑥ 客户数据中台

- **Company / Contact 主数据**：全局唯一，多源合并，字段级来源追溯
- **全域事件流**：每一次打开、点击、回复、访问官网、下载资料，都进同一条时间线
- **公海 / 私海机制**（直击「人走客凉」）：
  - 私海容量上限（防止业务员圈地不跟进）
  - **自动回收规则**：N 天无有效跟进 / M 天无回应 → 回公海，其他人可捡
  - 离职一键交接，历史沟通完整保留
- **客户资产沉淀率**（老板核心指标）：有完整联系方式 + 有沟通记录 + 有报价历史的客户占比

### ⑦ AI Agent 编排层

这是产品的技术护城河，也是与「AI 小助手」类产品的分水岭。

**层级模型**（参考截图 1 的 Agents / 任务 / 目标任务 三层，我们做实它的语义）：

```
Goal 目标（人设定）        "本季度在墨西哥市场获取 30 个高意向线索"
  ↓ Agent 规划
Plan 计划（可编辑）        1.海关数据筛选 → 2.决策人补全 → 3.西语内容 → 4.序列触达 → 5.回复分诊
  ↓ 拆解
Task 任务（可调度）        每个任务有输入/输出契约、预算上限、超时、重试策略
  ↓ 执行
Step 步骤（工具调用）      customs.search() / linkedin.enrich() / llm.write() / email.send()
  ↓ 记录
Event 事件（全量留痕）     可回放、可审计、可归因、可作为改进训练信号
```

**内置 Agent 清单（外贸专用，而非通用助理）**：

| Agent | 职责 | 触发方式 |
|---|---|---|
| `lead-hunter` | 多源找线索、评分、去重、入池 | 定时 / 目标驱动 |
| `contact-enricher` | 补全决策人邮箱、职级、社媒 | 事件驱动（新线索入池） |
| `inbox-triage` | 询盘分诊、摘要、意向打标、SLA 预警 | 事件驱动（新消息） |
| `reply-drafter` | 基于产品库+历史成交生成回复草稿 | 事件驱动 |
| `sequence-runner` | 执行多渠道序列，遵守限速与合规 | 调度 |
| `content-writer` | 选题→多语言成文→GEO 结构化 | 定时 / 人工 |
| `site-builder` | 站点生成、构建、部署 | 人工触发 |
| `seo-geo-auditor` | 收录/排名/AI 引用监测与建议 | 定时 |
| `deal-coach` | 商机停滞诊断、下一步建议、丢单归因 | 定时 |
| `order-tracker` | 订单节点跟催、客户进度通报草稿 | 事件驱动 |
| `deliverability-guard` | 发信域健康监控、自动降速/切换 | 常驻 |
| `compliance-officer` | opt-in 校验、退订同步、审计报告 | 常驻（拦截式） |

**人机协作（HITL）分级**——这是让老板敢用的关键：

| 级别 | 行为 | 适用 |
|---|---|---|
| L0 观察 | Agent 只给建议，人全手动 | 新客户上线首两周 |
| L1 草稿 | Agent 起草，人审核后发送 | **默认级别** |
| L2 有限自主 | 白名单动作自动执行（如线索评分、内部任务），外发仍需审核 | 熟悉后 |
| L3 目标自主 | 在预算/限速/合规护栏内自主执行，异常升级给人 | 成熟客户 + 低风险场景 |

每个 Agent 运行都有**运行日志与回放**：看到它调用了什么工具、拿到什么数据、为什么这么决策、花了多少 token/多少钱。

### ⑧ 角色化工作台

**业务员工作台**（回答「我今天该干什么」）：
- 昨夜新询盘 + AI 简报（含客户本地时间）
- 今日跟进清单（按 SLA 紧急度和成交概率排序，不按创建时间）
- 今日建议开发的 20 个新线索
- 我的漏斗与本月目标进度
- 卡住的商机（>14 天无进展）与 AI 诊断

**老板工作台**（回答「生意健康吗、钱该投哪」）：
- 业绩：本月/季度成交额、在手订单、预计回款
- **渠道 ROI 归因**：各渠道投入 vs 线索数 vs 成交额 vs 单客获客成本
- 团队健康度：人均产出、漏斗各阶段转化、首响达标率、僵尸客户占比
- **客户资产沉淀率** + 公海回收情况
- 风险预警：应收逾期、汇率敞口、单一客户依赖度、合规异常、发信域健康

## 五、差异化护城河（凭什么赢）

| 护城河 | 说明 | 竞品为什么难跟 |
|---|---|---|
| **闭环归因数据** | 从线索源头追到回款，形成「哪种线索/哪种话术/哪个市场最赚钱」的私有数据资产 | 拓客工具没有交付端数据，ERP 没有获客端数据 |
| **合规与送达率工程** | LIA 存档、opt-in 证据链、发信域健康、自动预热 | 需要长期工程投入，且短期不"性感"，多数厂商跳过 |
| **外贸专用 Agent 工具集** | 海关数据检索、报价测算、PI 生成、单证核对作为 Agent 原生工具 | 海外 AI SDR 完全没有这些概念 |
| **模型无关的编排层** | 多模型路由，模型能力提升直接转化为产品能力 | 单模型绑定的产品会被成本与能力波动卡死 |
| **行业知识库沉淀** | 客户自有的产品知识 + 成功话术 + 丢单原因 → RAG，越用越准 | 切换成本随时间指数上升 |

`工作台（双角色）` · `线索雷达` · `客户管理` · `客户 360` · `统一收件箱` · `触达序列` · `商机看板` · `报价与 PI` · `订单交付` · `AI 建站` · `内容工厂` · `AI Agents` · `经营分析` · `合规中心` · `系统设置`

用途：**对内对齐产品认知，对外做客户访谈与融资演示**。所有数字为模拟数据，不代表真实业绩。
